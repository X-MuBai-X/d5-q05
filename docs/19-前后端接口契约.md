## 1. 总体形态

- **仅 B 端**：单一后台端，顶栏中间是**账号切换器**；账号决定角色，角色决定可见页面与数据范围。
  角色之间**只有两处差异**：① 可见页面集合不同；② 数据可见范围不同（见 §3 权限矩阵）。
- 前端是**纯展示 + 表单发起**，所有业务判定在后端；前端不做任何额度/权限的二次判断
  （「不依赖前端隐藏」的越权阻断要求，见蓝图图 03）。
- 后端是 Go + SQLite（`modelquota`），默认监听 `http://127.0.0.1:8080`。
- 前端开发态用 Vite dev server（默认 `8443`），把 `/api` 代理到 Go 后端；
  生产态构建产物由 Go 以 `-web-dir` 目录托管。

## 2. 错误响应体（统一）

所有非 2xx 响应统一为：

```json
{ "code": "QUOTA_EXCEEDED", "message": "面向人的说明文本" }
```

- `code` 取自 §2 错误码矩阵，**是程序判断依据，不得随文案变化**；
- `message` 面向人，可读即可；
- `500` 一律返回 `{ "code": "INTERNAL_ERROR", "message": "服务内部错误，请稍后重试" }`，不泄露内部细节。

## 3. 认证与身份

### `POST /api/v1/auth/login`

请求（两种二选一）：

```json
{ "username": "ops", "password": "…" }
{ "secret": "sk-…" }
```

响应 `200`：

```json
{
  "token": "…",
  "identity": {
    "role": "OPS_ADMIN | TENANT_ADMIN | TENANT_APP",
    "subject_id": "…",
    "tenant_id": "…",
    "display_name": "…",
    "tenant_code": "GEEK-AI",
    "tenant_name": "…"
  }
}
```

- `role` 决定前端可见页面与请求范围；
- `tenant_id` 对 `OPS_ADMIN` 为空；
- 令牌既可放 `Authorization: Bearer <token>`，也可放 Cookie。

### `GET /api/v1/auth/whoami` → 同上 `identity` 结构

### `POST /api/v1/auth/logout` → `200 {"status":"logged_out"}`

`POST /api/v1/app/invoke` 响应 `200`：

```json
{
  "request": {
    "client_req_id": "req-app-a1-20250519-007",
    "status": "SUCCESS",
    "model": "Jinghua-Text-Omni-v1",
    "accepted_at": "2026-05-19T06:12:00Z",
    "finished_at": "2026-05-19T06:12:01Z",
    "latency_ms": 380,
    "quota_deducted": true,
    "error_code": "",
    "error_message": ""
  },
  "idempotent_hit": false,
  "usage": { "quota_limit": 10, "success": 3, "in_flight": 1, "available": 6 }
}
```

- 同编号同参数 → `200` 且 `idempotent_hit: true`（**零上游调用、零重复计量**）；
- 同编号改参数 → `409 IDEMPOTENCY_CONFLICT`；
- 额度耗尽 → `429 QUOTA_EXCEEDED`；
- 凭证停用 → `403 KEY_SUSPENDED`；租户停用 → `403 TENANT_SUSPENDED`；
- 上游失败 → `502 UPSTREAM_ERROR`；上游超时 → `504 GATEWAY_TIMEOUT`。

## 7. 错误码矩阵（§2 完整表）

| HTTP | code | 触发条件 | 调用上游 | 扣额 |
|---|---|---|---|---|
| 200 | `SUCCESS` | 上游 2s 内成功 | 是 | 实扣 1 |
| 200 | `IDEMPOTENT_HIT` | 同号同参重复 | 否 | 否 |
| 400 | `INVALID_PARAMS` | 缺 `client_req_id` 等 | 否 | 否 |
| 401 | `KEY_NOT_FOUND` | 凭证无效或未提供 | 否 | 否 |
| 403 | `KEY_SUSPENDED` | 凭证已停用 | 否 | 否 |
| 403 | `TENANT_SUSPENDED` | 租户已停用 | 否 | 否 |
| 403 | `SCOPE_DENIED` | 越权查询他方请求 | 否 | 否 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同编号改参数 | 否 | 否 |
| 429 | `QUOTA_EXCEEDED` | `Available ≤ 0` | 否 | 否 |
| 502 | `UPSTREAM_ERROR` | 上游明确失败 | 是 | 否（释放预占） |
| 504 | `GATEWAY_TIMEOUT` | 上游 > 2s | 是 | 否（释放预占） |

管理类接口另用：`CREDENTIAL_LIMIT_REACHED`、`TENANT_NAME_REQUIRED`、`QUOTA_FLOOR_VIOLATION`、
`REASON_REQUIRED`、`QUOTA_RANGE_INVALID`、`TENANT_SCOPE_REQUIRED`、`NOT_FOUND`、`INTERNAL_ERROR`。

## 10. 页面与字段（严格照原型蓝图）

### 图 01 运营总控大盘
- 顶部：核算基准日（UTC）、平台概览 KPI；

- 迟到响应诊断池：`client_req_id | 原结论 | 迟到 ms | 处理：仅归档`。

### 图 02 租户控制台
- 共享日额度条：`Limit 10 − 成功 3 − 在途 1 ＝ 可用 6`，并注明口径；

### 图 03 应用调用台
- 发起调用：`model`（单模型非流式）、`client_req_id`、`prompt`、`发送请求`；

- 防越权查询器：输入 `client_req_id` → 本凭证 200 / 兄弟应用 403 SCOPE_DENIED / 跨租户 403 且 0 行 / 伪造 tenant_id 被丢弃；
- 我的请求表：`client_req_id | 受理时间 | 状态 | 扣额`。

### 图 05 日终核查与 CLI
- 核查清单 5 项打勾：`扣额 ≡ 成功请求数`、`在途归零`、`无超卖`、`迟到包补扣 = 0`、`变更/停用影响可追溯`；
- 变更追溯：`时间 | 变更 | 操作人`（含被拒绝）；
- 跨租户校验：`GEEK-AI ↔ SHIELD-SEC`；
- 对账 CLI 控制台：展示**后端真实输出**（由 `cmd/reconcile` 产生），不是前端拼的假日志。

## 11. 对账 CLI 契约

```
reconcile-cli --tenant <代号|ID> --date <YYYY-MM-DD> [--db <路径>] [--verify] [--json]
```

退出码：`0` 账实一致；`1` 存在差异（输出明细）；`2` 参数/环境错误。

前端图 05 的 CLI 控制台**必须调用真实 CLI 或展示其真实输出**，
不得在前端拼装日志字符串冒充。
