# 14 · 分支实现链对照表（题目 05）

> 用途：把**每一条业务规则与每一组场景**从「用户提示」一路对到「产物版本」与「验证证据」，
> 使「提示 → 实现 → 验证」的链条可逐条定位，而不是只看最终文件或提交总数。
>
> 取材原则：
> - 提示与时刻取自 `evidence/会话事件清单.jsonl`（原始事件，含载体与时间戳）；
> - 首次落盘时刻取自 `evidence/过程时序清单.md`（由事件清单机器反推，不依赖文件最终修改时间）；
> - 产物版本取自 `git log dev/05`；
> - 验证证据取自 `evidence/scenario-verify.log`、`evidence/api-full-test.log`、
>   `evidence/independent-test-report.md`、`evidence/independent-acceptance-report.md`。
>
> 说明：题面允许「一条提示覆盖多个分支」，并不要求每条业务分支都有独立的一条用户提示；
> 本表按分支展开的是**实现步骤与其验证**，提示列如实标注该分支由哪一条提示覆盖。
