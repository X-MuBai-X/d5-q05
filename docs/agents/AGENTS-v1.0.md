## 1. 范围边界

1. 本仓库只实现题面第 5 题「企业模型服务的配额开通、调用、停用与用量核查」。
2. 题面快照见 `docs/_question-05.md`，共同要求见 `docs/_common-requirements.md`。
3. 需求分析结论见 `docs/01-需求分析.md`；假设清单 A1–A13 与确认结论 Q1–Q12 是本文件的依据。

## 2. 技术选型

| 项目 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.27 | 题目要求 Go 核心业务 |
| 数据库 | SQLite（`modernc.org/sqlite`） | 纯 Go 驱动，无需 CGO（本机无 C 编译器） |
| 依赖数 | 仅 1 个第三方依赖 | 降低供应链与审计成本 |
| HTTP | 标准库 `net/http` + `html/template` | 不引入 Web 框架 |
| 并发控制 | 数据库层条件 UPDATE 原子占额度 | 满足 R2「防止并发超过上限」 |
| 上游模拟 | 自建 `cmd/mockupstream` | 共同要求允许可控 HTTP 模拟服务 |

禁止引入 ORM、Web 框架、外部中间件与需要 CGO 的依赖。

## 3. 分层与依赖方向

```
httpapi  →  service  →  store  →  domain
                    ↘  upstream
```

- `domain` 只放纯类型与纯函数，不依赖数据库与网络。
- `store` 只做持久化，业务判断收敛到 `service`。
- 计量口径、幂等、权限判定、留痕统一在 `service` 收口。

## 4. 计量口径（R2 / R4 / R5）

```
当日占用额度 = 当日成功数 + 当日处理中数
剩余额度     = 日额度 − 当日占用额度
```

- 受理：处理中 +1。
- 成功：处理中 −1、成功 +1，总占用不变，计入成功量。
- 失败 / 超时（>2s）：处理中 −1，释放占用，不计成功量。
- 失败与超时是**两个独立终态**，但计量口径相同（Q1）。
- 迟到结果只进诊断表，不改终态、不追加扣额（R4 / Q11）。
- 日期归属 = 首次受理时刻的 UTC 自然日，受理后固定（R2 / Q10）。
- 降额下限 = UTC 当日成功数 + 处理中数（R5 / Q2）；额度范围 `0..100000`（Q4）。
- 配额是租户级单一数值，所有凭证共享（R2）。
- 幂等命中不重复计量（R3）。
- 被拒绝的尝试写独立表，不占用 `request_no`，增额后可用同一编号重试（R8 / Q7）。

## 5. 身份与权限（R1 / R7）

1. 身份只来自服务端签发的会话令牌；请求参数里的租户/用户编号不被采信。
2. 越权尝试必须**显式拒绝**，不能静默忽略。
3. 运营：开通租户、调整配额、停用租户、跨租户核查，无租户归属。
4. 客户管理员：管理本租户凭证、查看本租户用量。
5. 应用凭证：发起调用、查询本凭证请求；不可查看租户级用量汇总（Q3）。
6. 口令与密钥只存摘要，明文只在创建时返回一次。

## 6. 代码规范

1. `gofmt` 零差异，`go vet ./...` 无告警。
2. 注释与文档使用中文；导出标识符须有以标识符名开头的注释。
3. 领域错误用哨兵错误 + `errors.Is`；包装用 `%w`。
4. 页面模板与 `layout.html` 一起解析，每个页面只 `define "content"`。
5. 表单与 JSON 走同一业务逻辑。

## 7. 测试要求

1. 整体覆盖率 ≥ 85%，核心业务包分别 ≥ 85%。
2. 必须覆盖并发争抢最后一个额度名额的场景。
3. 竞态检测 `go test ./... -race`。
4. 禁止伪造测试结果，未执行的检查记「待补证」。
