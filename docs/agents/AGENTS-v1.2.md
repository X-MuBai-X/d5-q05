## 2. 技术选型（已定，禁止随意更换）

| 项目 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.27 | 题目要求 Go 核心业务 |
| 数据库 | SQLite（`modernc.org/sqlite` v1.62.0） | 纯 Go 驱动，**无需 CGO**（本机无 C 编译器） |

| 并发控制 | 数据库层条件 UPDATE 原子占额度 | 见 §4 计量口径 |
| 上游模拟 | 自建 `cmd/mockupstream` | 共同要求允许可控 HTTP 模拟服务 |

**禁止**：引入 ORM、引入 Web 框架、引入 Redis/MQ 等外部中间件、引入需要 CGO 的依赖。

## 3. 目录结构与分层

```
cmd/server/            服务入口（参数解析、装配、优雅关闭）
cmd/mockupstream/      模拟上游模型服务
internal/domain/       纯类型与纯函数：实体、状态枚举、计量口径计算、参数校验
internal/store/        SQLite 持久化；schema.sql 是数据库结构的唯一事实来源
internal/service/      业务编排：租户开通、配额调整、凭证、调用受理与计量、日终核查
internal/upstream/     上游模型调用客户端契约与 HTTP 实现
internal/httpapi/      HTTP 接口、RBAC、页面模板与渲染
docs/                  需求分析、原型、任务规划、假设清单、部署说明、AI 使用说明
skills/                自编 Skill：业务专项（quota-guard）与验收检查（acceptance-audit）
evidence/              真实执行证据（测试报告、部署记录、核验日志）
```

**分层依赖方向（单向，不可逆向）**：

```
httpapi  →  service  →  store  →  domain
                    ↘  upstream
domain 不依赖任何其他内部包
```

- `internal/domain` 只放纯函数，便于对计量口径做精确单元测试，**不得**引入数据库或网络依赖。
- `internal/store` 只做持久化，不含业务判断（唯一例外是 `ReserveInflight` 的原子条件判定，
  它是 R2「防止并发超过上限」的实现手段，判定口径由 `domain` 的规则定义）。
- `internal/service` 是唯一的业务编排层：计量口径、幂等、权限判定、留痕都在这里收口。

## 4. 计量口径硬约束（最容易写错，改动前必读）

```
当日占用额度 = 当日成功数 + 当日处理中数
剩余额度     = 日额度 − 当日占用额度（不得为负）
```

| 路径 | 处理中 | 成功数 | 总占用 | 是否计入成功量 |
|---|---|---|---|---|
| 受理成功（占用额度） | +1 | 0 | +1 | 否 |
| 上游成功 | −1 | +1 | 不变 | 是 |
| 上游明确失败 | −1 | 0 | −1 | 否 |
| 上游超时（>2s） | −1 | 0 | −1 | 否 |
| 受理前被拒绝 | 不变 | 不变 | 不变 | 否 |

1. **成功、失败、超时是三个独立终态**（确认结论 Q1），但失败与超时的**计量口径相同**。
2. **失败与超时必须释放已占用的额度**，且都**不计成功量**（R4）。
3. **迟到结果只进 `diagnostics` 表**：不改终态、不追加扣额、不计入成功量（R4 / 确认结论 Q11）。
4. **额度归属日期 = 首次受理时刻的 UTC 自然日**，受理后固定，跨日完成不迁移（R2 / 确认结论 Q10）。
5. **降额下限 = UTC 当日成功数 + 处理中数**（R5 / 确认结论 Q2）；额度范围 `0..100000`（确认结论 Q4）。
6. **配额是租户级单一数值**，租户下所有凭证共享（R2）。
7. **幂等命中不重复计量**：不新增记录、不占额度、不调用上游（R3）。
8. **被拒绝的尝试写入独立表 `rejected_attempts`**：不占用 `request_no` 唯一性，
   因此增额后可用同一编号重试（R8 / 确认结论 Q7）。

> ⚠️ 任何改动触及以上 8 条，必须同步补充或修改 `internal/domain`、`internal/store`、
> `internal/service` 三层的对应单元测试，并在 `skills/quota-guard` 全部通过后才可提交。

## 5. 身份与权限硬约束

1. **身份只来自服务端签发的会话令牌**。请求参数里的 `tenant_id` / `user_id` **一律不被采信**；
   越权尝试要**显式拒绝**（返回 4xx），不能静默忽略，否则无法断言越权已被阻断。
2. 三类主体：`ops`（平台运营）、`tenant_admin`（客户管理员）、`credential`（客户应用凭证）。
3. 职责边界：
   - 运营：开通租户、调整配额、停用租户、跨租户核查；**没有租户归属**，跨租户查询必须显式指定 `tenant_id`。
   - 客户管理员：管理**本租户**的凭证、查看**本租户**用量；**不能**为其他租户创建凭证。
   - 应用凭证：发起调用、查询**本凭证**创建的请求；**不能**查看租户级用量汇总（确认结论 Q3）。
4. 凭证的创建与停用只允许客户管理员（凭证所属租户由服务端从调用者身份推导）。
5. **口令与密钥只存摘要**（`domain.HashSecret`）；明文只在创建时返回一次。

## 6. 代码规范

1. `gofmt` 必须零差异：`gofmt -l .` 输出为空。
2. `go vet ./...` 必须无告警。
3. 注释与文档使用**中文**；导出标识符必须有以标识符名开头的注释（Go 惯例）。
4. 错误处理：领域错误用 `domain` 包的哨兵错误（`ErrXxx`），用 `errors.Is` 判断；
   包装错误必须用 `%w`。
5. **HTTP 500 的响应不得透出内部细节**（数据库错误、路径、SQL）；细节写服务端日志。
6. 页面模板：每个页面模板只 `define "content"`，与 `layout.html` 一起解析；
   `map[domain.RequestStatus]int` 之类**键类型非 string 的映射不能在模板里用字符串下标**，
   必须通过类型安全的方法（如 `DailyReport.CountOf`）取值。
7. 表单与 JSON 双通道：HTML 表单提交 `application/x-www-form-urlencoded`，
   接口调用提交 `application/json`；两者走同一业务逻辑。

## 7. 测试要求

1. **单元测试覆盖率**：整体 ≥ 85%，核心业务包（`domain` / `store` / `service` / `httpapi` / `upstream`）
   **分别** ≥ 85%。用 `go test ./... -coverprofile=coverage.out` + `go tool cover -func` 统计。
2. 核心并发场景必须有测试：
   - 并发争抢**最后一个**额度名额时，只能有一个请求成功（`store` 与 `service` 两层各一）；
   - 并发提交**同一请求编号**时，按幂等处理而不是抛唯一约束错误。
3. 竞态检测：`go test ./... -race`（需要 CGO 与 C 编译器）。
4. 测试不得依赖真实网络；上游用 `httptest` 或测试替身。
5. **禁止伪造测试结果**。未执行的检查一律记「待补证」。

## 9. 自编 Skill 使用约定

本仓库自带两个 Skill，位于 `skills/`：

| Skill | 用途 | 触发时机 |
|---|---|---|
| `quota-guard` | 配额计量口径守卫 | 改动 `domain` / `store` / `service` 的计量逻辑后 |
| `acceptance-audit` | 验收逐条核查 | 交付前自检、按题目清单核对时 |

**必须真实调用并把原始输出存入 `evidence/`**，调用记录见 `docs/08-Skill使用记录.md`。
