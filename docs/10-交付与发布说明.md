| 平台 | GitHub | Gitee |

> 在未由 MCP `create_repo` 重建前**不能**作为建仓证据。

### 4.1 一键驱动（拿到可建仓凭据后）

```powershell
$env:GITHUB_PERSONAL_ACCESS_TOKEN = "<classic PAT: ghp_... ，需 repo scope>"
python scripts\release-github.py --repo . --owner <owner> --name <repo>
```

脚本按第 8 节顺序执行 8 步，任一步失败即如实记录原因并停止，不跳过、不伪造后续结论：

| 步骤 | 动作 | 产物 |
|---|---|---|
| 1 | 推送 `main` 与 `dev/05` 到远端 | 远端分支 |
| 2 | MCP `create_pull_request`（描述含第 4 条要求的 6 项要素） | `evidence/github-mcp/*-create_pull_request.json` |
| 3 | 配置 main 分支保护：禁直推 / 禁删除 / 禁强推 / 要求 PR 合并 + 状态检查（**GitHub MCP 未暴露保护类工具，此步走 REST API 并如实标注**） | — |
| 4 | 读取并归档保护规则 | `evidence/branch-protection.json` |
| 5 | MCP `merge_pull_request`（保留原始提交；合并消息按提交规范关联 `#16221249`） | `evidence/github-mcp/*-merge_pull_request.json` |
| 6 | 在**合并提交**上重跑质量门禁 | `evidence/main-gate-<短SHA>.log` |
| 7 | 在合并版本上重新部署 | `evidence/deployment-main.log` |
| 8 | 复跑交付链路自检 | `evidence/delivery-check.md` / `.json` |
