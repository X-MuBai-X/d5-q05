# 04 · 部署与使用说明（题目 05）

> 本文件描述**如何真实运行**本项目，以及每个可操作页面的用法。
> 文中所有命令均可直接复制执行；执行结果见 `evidence/` 目录。

## 1. 交付范围

本仓库只实现题面第 5 题「企业模型服务的配额开通、调用、停用与用量核查」，
包含 Go 核心业务、HTTP 接口、三个可操作页面、SQLite 数据库、模拟上游服务、
单元测试、CI 流水线与两个自编 Skill。其余 19 题不在本仓库范围内。

## 2. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Go | ≥ 1.27 | 开发环境实测 `go1.27.1 windows/amd64` |
| CGO | **不需要** | 数据库驱动 `modernc.org/sqlite` 是纯 Go 实现 |
| C 编译器 | 仅竞态检测需要 | `go test -race` 需要 CGO；CI 的 ubuntu runner 自带 gcc |
| 外部服务 | 不需要 | 上游模型服务由本仓库自带的模拟上游提供 |

> 若本机要执行竞态检测，可安装 MinGW-w64：
> `winget install --id BrechtSanders.WinLibs.POSIX.UCRT --exact`
> 装完后需把其 `bin` 目录加入 PATH，并设置 `CGO_ENABLED=1`。

## 4. 部署

### 4.1 一键脚本（Windows / PowerShell）

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy-local.ps1
```

脚本会依次完成：**端口预检 → 构建 → 启动模拟上游 → 启动业务服务 → 健康检查 → 业务冒烟**，
并把全过程写入 `evidence/deployment.log`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-Port` | `8080` | 业务服务端口 |
| `-UpstreamPort` | `9091` | 模拟上游端口 |
| `-DbPath` | 自动生成 `deploy/data/app-<时间戳>.db` | 数据库路径 |
| `-LogFile` | `evidence/deployment.log` | 部署日志写入位置 |
| `-SkipSmoke` | 关 | 只跳过业务冒烟（用于五组场景验证，需要未污染的全新数据库） |
| `-KeepRunning` | 关 | 仅提示服务仍在运行 |

> **端口预检是必须的**：端口被上一轮实例占用时，新进程会启动失败，
> 而健康检查仍会打到旧进程上——看起来「服务正常」，实际测的不是刚构建的产物。
> 预检失败时脚本会直接报错退出。

停止服务（回退）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop-local.ps1
```

### 4.2 手工启动（Linux / macOS / Windows 通用）

```bash
# 终端 1：模拟上游模型服务
go run ./cmd/mockupstream -addr 127.0.0.1:9091

# 终端 2：业务服务
go run ./cmd/server -addr 127.0.0.1:8080 \
    -db ./deploy/data/app.db \
    -upstream http://127.0.0.1:9091 \
    -enable-test-hooks
```

### 4.3 服务参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | 监听地址 |
| `-db` | `./data/app.db` | SQLite 数据库路径（目录会自动创建） |
| `-upstream` | `http://127.0.0.1:9091` | 上游模型服务地址 |
| `-enable-test-hooks` | `false` | 是否开放平台侧测试钩子（含迟到结果注入） |
| `-seed` | `true` | 是否写入预置数据（幂等，重复启动不会重复写入） |

### 4.4 教学验收环境说明

题目要求「部署到指定教学验收环境，须有可访问的服务地址和真实部署记录」。
本项目的落地方式是**本机真实进程部署**：

- 服务地址：`http://127.0.0.1:8080`（真实监听进程，非 mock）
- 模拟上游：`http://127.0.0.1:9091`
- 部署记录：`evidence/deployment.log`（含 PID、健康检查响应、冒烟逐项结论）
- 冒烟记录：`evidence/smoke-test.log`

> **待补证**：本机没有可用的远程教学验收主机，也没有可用的容器运行时
> （Docker daemon 未运行）与 GitHub 远端仓库（无 GitHub MCP、无 `gh` CLI），
> 因此无法产生远程部署地址、容器编排记录与 GitHub PR / 分支保护记录。
> 详见 `docs/09-AI使用说明.md` 的「环境限制与待补证清单」。

## 6. 三个可操作页面

| 页面 | 地址 | 进入方式 | 能做什么 |
|---|---|---|---|
| 运营工作台 | `/ops` | 用 `ops` 登录 | 开通租户、调整额度、停用租户、按租户与日期做日终核查、看迟到结果诊断 |
| 租户管理台 | `/admin` | 用 `admin-a` / `admin-b` 登录 | 创建/停用本租户凭证、查看本租户额度与成功量、查看本租户调用记录与被拒绝尝试 |
| 应用调用台 | `/app` | 用凭证密钥登录 | 发起模型调用（可选上游场景）、查看本凭证的调用记录 |

三个页面都有 **UTC 自然日日期选择器**（缺省为 UTC 今日）。

### 6.1 典型操作路径

```
1. 运营登录 → /ops → 「开通租户」填名称与日额度 → 提交
2. 运营 → 「调整额度」改数值，填变更原因（必填）→ 提交
3. 租户管理员登录 → /admin → 「创建凭证」填名称 → 提交（密钥只显示一次，务必保存）
4. 用该密钥登录 → /app → 选择上游场景 → 「发起调用」
5. 运营 → /ops → 选择日期 → 查看日终核查（成功/失败/超时/处理中/被拒绝五类分列 + 一致性核对）
```

## 7. 接口清单

所有接口都支持 **JSON**（`Content-Type: application/json`）与
**HTML 表单**（`application/x-www-form-urlencoded`）两种提交方式。

### 7.1 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | 管理员用账号口令登录、应用用凭证密钥登录，签发会话令牌 |
| POST | `/api/v1/auth/logout` | 登出并销毁会话 |
| GET | `/api/v1/auth/whoami` | 查询当前身份 |
| GET | `/healthz`、`/readyz` | 健康检查（无需认证） |

### 7.2 运营（跨租户核查）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/ops/tenants` | 列出全部租户 |
| POST | `/api/v1/ops/tenants/open` | 开通租户（新建或恢复）并设置日额度 |
| POST | `/api/v1/ops/tenants/quota` | 调整日额度（原因必填，降额受下限约束） |
| POST | `/api/v1/ops/tenants/disable` | 停用租户（原因必填） |
| GET | `/api/v1/ops/report/daily?tenant_id=&day=` | 日终核查报表 |
| GET | `/api/v1/ops/diagnostics?tenant_id=` | 迟到结果等诊断记录 |
| POST | `/api/v1/ops/clock` | 调整教学时钟偏移（仅影响"当前时间"） |

### 7.3 租户管理员

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/credentials` | 本租户凭证列表 |
| POST | `/api/v1/admin/credentials/create` | 创建本租户凭证（返回一次性密钥） |
| POST | `/api/v1/admin/credentials/disable` | 停用本租户凭证（原因必填） |
| GET | `/api/v1/admin/usage?day=` | 本租户用量与剩余额度 |
| GET | `/api/v1/admin/requests?day=` | 本租户调用记录与被拒绝尝试 |

### 7.4 客户应用

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/app/invoke` | 发起模型调用（需本租户全局唯一请求编号） |
| GET | `/api/v1/app/requests?day=` | 本凭证创建的请求 |
| GET | `/api/v1/app/request?request_no=` | 单个请求详情 |

### 7.5 调用示例

```bash
# 1. 运营登录
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ops","password":"ops-secret"}'

# 2. 调整配额（原因必填）
curl -s -X POST http://127.0.0.1:8080/api/v1/ops/tenants/quota \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $OPS_TOKEN" \
  -d '{"tenant_id":"tenant-a","daily_quota":20,"reason":"客户扩容"}'

# 3. 客户管理员创建凭证
curl -s -X POST http://127.0.0.1:8080/api/v1/admin/credentials/create \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"name":"app-1"}'

# 4. 应用发起调用（同一编号重复提交即幂等）
curl -s -X POST http://127.0.0.1:8080/api/v1/app/invoke \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $APP_TOKEN" \
  -d '{"request_no":"req-001","model":"text-1","prompt":"你好"}'

# 5. 日终核查
curl -s "http://127.0.0.1:8080/api/v1/ops/report/daily?tenant_id=tenant-a" \
  -H "Authorization: Bearer $OPS_TOKEN"
```

## 8. 模拟上游场景

`cmd/mockupstream` 通过请求体的 `params.scenario` 或请求头 `X-Mock-Scenario` 选择场景：

| 场景 | 行为 | 平台侧应有结论 |
|---|---|---|
| `success` | 正常返回（默认） | 终态 `success`，成功量 +1 |
| `fail` | 返回 500 | 终态 `failed`，释放额度、不计成功量 |
| `timeout` | 挂起不响应 | 平台 2 秒判定超时，终态 `timeout`，释放额度、不计成功量 |
| `duplicate` | 同一编号返回与首次一致的内容 | 平台侧幂等命中，不重复计量 |
| `slow_success` | 延迟 3 秒后返回成功 | 平台已判超时并归还额度，该结果属迟到结果，只进诊断表 |

## 9. 验收与冒烟

```bash
# 业务冒烟（39 项断言）
BASE_URL=http://127.0.0.1:8080 bash scripts/smoke-test.sh
```

覆盖：健康检查、登录与未认证拒绝、越权拒绝、配额调整与原因必填、额度越界拒绝、
凭证创建与一次性密钥、跨租户创建凭证拒绝、运营代建凭证拒绝、调用成功、幂等重放、
参数冲突拒绝、编号缺失与格式非法拒绝、应用只能查本凭证、并发争抢最后一个额度
（8 并发 → 恰好 1 成功 7 拒绝）、日终核查五类分列与一致性核对、停用后拒绝受理。

```bash
# 单元测试与覆盖率
go test ./... -count=1 -coverprofile=evidence/coverage.out -covermode=atomic
python scripts/coverage-summary.py --profile evidence/coverage.out --out evidence/coverage-summary.txt

# 格式与静态检查
gofmt -l .        # 必须无输出
go vet ./...      # 必须无告警
```

### 9.1 竞态检测（需要 CGO 与 C 编译器）

Go 的竞态检测器依赖 cgo，因此需要可用的 C 编译器。

- **Linux / macOS / 有 gcc 的 Windows**：直接执行

  ```bash
  go test ./... -count=1 -race
  ```

- **本机没有 C 编译器时**（本项目实际采用的方式）：用官方 `golang:1.27` 容器执行，
  镜像自带 gcc。本仓库提供 `scripts/race-test.sh` 封装了这条命令并把原始输出
  写入 `evidence/race-test.log`：

  ```bash
  docker run --rm -v "$PWD:/work" -v quota-gomodcache:/go/pkg/mod -w /work \
    -e GOPROXY=https://goproxy.cn,direct -e CGO_ENABLED=1 \
    golang:1.27 sh scripts/race-test.sh
  ```

  本次实际执行结果：`evidence/race-test.log`（退出码 0，全部包通过，未检出数据竞争）。

### 9.2 五组完整工作场景逐条验证

题面要求的五组场景由 `scripts/scenario-verify.py` 逐条断言（共 73 条）：

```bash
# 用全新数据库部署一个独立实例（停用不可逆，重复跑必须换新库）
powershell -ExecutionPolicy Bypass -File scripts/deploy-local.ps1 \
    -Port 8081 -UpstreamPort 9092 -SkipSmoke -LogFile evidence/deployment-scenario.log
python scripts/scenario-verify.py --base-url http://127.0.0.1:8081 \
    --out evidence/scenario-verify.log --json-out evidence/scenario-verify.json
```

覆盖范围：开通使用、活动增额、事故处置、上游异常（失败/超时/迟到成功/重复请求/
最后一个额度并发争抢）、日终核查（跨日、两租户隔离、权限差异）。

> `-SkipSmoke` 只跳过**冒烟**，不会跳过构建、健康检查与启动；
> 端口预检失败会直接退出，避免「测到的不是刚构建的产物」。

## 10. CI/CD

`.github/workflows/ci.yml` 定义两条流水线：

1. **质量门禁**：`gofmt` → `go vet` → 单元测试 → 覆盖率门禁（整体与核心包 ≥85%）→
   `go test -race` → 上传覆盖率原件与测试日志。
2. **业务冒烟**：真实启动模拟上游与业务服务 → 执行 `scripts/smoke-test.sh` →
   收集日志作为制品。

触发条件：推送到 `main` 或 `dev/**`、向 `main` 提 PR、手动触发。

## 11. 恢复与回退

| 场景 | 办法 |
|---|---|
| 停止服务 | `scripts/stop-local.ps1`，或直接结束进程 |
| 回退到初始预置状态 | 删除 `deploy/data/*.db` 后重启，服务会重新写入预置数据 |
| 代码回退 | `git revert <提交>`；主分支不直接强推 |
| 数据库结构变更 | `internal/store/schema.sql` 是唯一事实来源，由 `go:embed` 加载且建表幂等 |
